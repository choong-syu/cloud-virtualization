# 7주차 실습 — 교수자 배포·진행 안내

## 수업 목표와 범위

최신 수정: runc 메모리 한도 변경·재생성 비교와 학생용 자원 삭제 단계는 제외했습니다. Docker A/B의 128 MiB·256 MiB 비교는 유지합니다. 학생용 README는 자료 준비부터 본문 실습까지 명령 블록 01~68번으로 연속 번호를 부여했습니다. 자료 준비 앞의 선택적 curl·인증서 설치 안내는 접기 영역에 있습니다.

이번 주는 Linux 기능을 수작업으로 다시 구성하지 않습니다. 학생이 이미 배운 현상을 **runc 설정 → 실제 실행 → Docker 옵션 → 실제 실행**으로 연결합니다.

| 구간 | 권장 시간 | 집중할 내용 |
| --- | ---: | --- |
| 준비 | 10~15분 | 패키지와 rootfs 준비, 실행 위치 확인 |
| runc 셸 | 15분 | config.json과 rootfs, 내부 hostname·PID |
| runc 수명주기 | 10분 | created/running, 지정된 128 MiB 한도 확인 |
| Docker 설치·실행 | 15분 | 이미지와 컨테이너 구분, A/B 조건 |
| Docker 내부 관찰 | 20분 | 같은 프로세스, Cgroup, 파일 변경 |
| 네트워크·관리 프로세스 | 10분 | veth·Bridge, containerd·shim |
| 웹 서비스 | 5분 | HTTP 200과 요청 로그 확인 |

패키지와 이미지 다운로드 시간이 길면 수업 전 준비 시간을 별도로 둡니다. CPU 부하/OOM, veth 수작업 생성, Seccomp 규칙 직접 작성은 이전 주차에 이미 했으므로 반복하지 않습니다.

## 배포 파일

GitHub의 원본 파일 세 개를 각 학생 계정의 홈 아래에 배치합니다. 문서와 그림은 GitHub에서 읽으므로 VM에 내려받을 필요가 없습니다.

```text
/home/학생계정/week07/
  prepare.sh
  configs/shell.json
  configs/sleep-128.json
```

설정 파일은 학생이 짧은 `cp` 명령으로 선택합니다. JSON 전체를 타이핑하게 하거나 `jq` 수정 문법을 추가로 배우게 하지 않습니다. 학생은 선택한 파일의 실제 내용과 적용 결과를 읽습니다.

`prepare.sh`는 **일반 사용자**로 실행해야 합니다. Ubuntu 24.04와 Cgroup v2를 확인한 뒤 필요한 도구를 설치합니다. 이전 rootfs가 있으면 7주차 폴더에 복사하며, 없으면 정적 BusyBox로 같은 역할의 파일 트리를 준비합니다. 이전 rootfs 원본이나 호스트 hostname을 바꾸지 않습니다.

검토 VM에서는 `sudo -i`와 일반 sudo 명령 모두 비밀번호 없이 실행됩니다. 단순히 `sudo -v`로만 권한을 점검하면 검증 정책 때문에 비밀번호를 요구할 수 있어, 스크립트는 `sudo -n true`를 먼저 확인하도록 했습니다. root 로그인 셸에서 시작했다면 `exit`로 학생 계정에 돌아와 진행합니다.

## 배포 방식

### 교수자가 사전 배포하는 경우

저장소의 `prepare.sh`, `configs/shell.json`, `configs/sleep-128.json`을 위 디렉터리 구조대로 학생 홈의 `week07`에 배치합니다. SSH 게이트웨이에 연결할 때 사용한 계정 문자열과 대상 VM을 그대로 이용하되, 파일 전송에는 환경에 맞는 SFTP/SCP 도구를 사용합니다. 학생은 배포 완료 후 README의 명령 01로 자료 폴더에 이동하고, 다운로드 명령 02~03을 건너뛰어 명령 04부터 진행합니다.

비밀번호를 README, 스크립트 또는 GitHub 저장소에 기록하지 않습니다. 게이트웨이 비밀번호와 VM의 sudo 비밀번호가 같은지 별도로 확인합니다.

### GitHub에서 학생이 직접 받는 경우

학생은 [7주차 튜토리얼](README.md)의 다운로드 명령으로 `prepare.sh`, `configs/shell.json`, `configs/sleep-128.json`을 GitHub에서 직접 받습니다. 세 파일을 모두 받은 뒤 `bash prepare.sh`를 실행합니다. Git 설치나 저장소 복제, 압축 해제는 필요하지 않습니다. 문서와 그림은 GitHub에서 읽습니다.

자료가 사전 배포된 학생은 다운로드를 건너뛰어 기존 파일을 유지합니다. 수정 사항은 저장소의 해당 원본 파일에만 반영합니다. 학생이 다시 다운로드하면 수정된 파일을 받으며, VM에 이미 받은 파일이 자동으로 갱신되지는 않습니다. 재다운로드는 같은 이름의 파일을 덮어쓰므로 학생이 직접 수정한 파일은 먼저 별도로 보관하도록 안내합니다.

## 실습용 설정의 의도

| 파일 | 프로그램 | 터미널 | 메모리 | CPU |
| --- | --- | --- | --- | --- |
| shell.json | `/bin/sh` | true | 별도 지정 없음 | 별도 지정 없음 |
| sleep-128.json | `/bin/sleep 3600` | false | 134217728바이트 | quota 50000 / period 100000 |

두 파일은 PID·UTS·Mount·Network·IPC·Cgroup Namespace를 요청합니다. runc의 rootfs는 읽기 전용이고, 관찰에 필요한 procfs·sysfs·Cgroup을 마운트합니다. runc 설정에서는 Capability 집합을 비우고 `noNewPrivileges`를 적용했습니다. 별도의 Seccomp 프로필은 포함하지 않았습니다. **Docker의 기본 보안 정책과 같다고 설명하지 않습니다.**

앞선 runc 실습은 네트워크 연결을 구성하지 않습니다. Docker 구간의 Bridge/veth 자동 구성과 역할을 구분합니다.

## 설명할 때 놓치지 않을 사항

- `created` 상태에도 내부 준비 프로세스의 PID는 있을 수 있습니다. 지정한 프로그램이 시작됐는지는 상태 전이로 설명합니다.
- `runc run` 포그라운드 셸은 exit로 끝납니다. create/start로 실행한 sleep은 이번 수업의 관찰 대상으로 유지합니다.
- `docker inspect`의 호스트 PID와 내부 PID 1은 같은 프로그램을 서로 다른 관점에서 본 값입니다.
- Cgroup 파일의 숫자와 `docker stats`의 사용량을 구분합니다. `--cpus=0.5`는 계속 50%를 쓰라는 의미가 아닙니다.
- 같은 이미지에서 만든 A/B라도 컨테이너별 파일 변경 내용은 공유되지 않습니다.
- Docker 사용자 정의 Bridge에서의 이름 해석과 Linux Bridge의 패킷 전달을 구분합니다.
- `Seccomp: 2`만으로 특정 시스템 호출의 차단 여부를 알 수 없습니다.
- runc는 작업 후 종료될 수 있습니다. 관리 프로세스 목록을 호출 순서의 증명으로 제시하지 않습니다.
- `localhost:8080`은 명령을 실행한 VM을 가리킵니다. 학생 PC의 localhost와 다릅니다.

## VM 변경 범위

설치: Ubuntu 패키지의 runc, Docker Engine(`docker.io`)과 의존성 및 관찰 도구.

생성: `~/week07/bundle/rootfs`, 설정 파일 사본, runc 식별자 `cv7-shell`·`cv7-demo`, Docker 컨테이너 `cv7-a`·`cv7-b`·`cv7-web`, Docker 네트워크 `cv7-net`.

학생용 자원 삭제 단계는 제외했습니다. 수업은 웹 서버 응답과 로그 확인으로 마치므로 컨테이너와 네트워크가 남습니다. sleep은 지정된 한 시간 후 종료되며, 웹 서버와 실행 상태·네트워크의 후속 관리는 교수자가 담당합니다. 재수업 전에는 같은 이름의 실행이 남아 있는지 확인합니다.

Docker 설치는 호스트에 서비스와 기본 네트워크 설정을 추가합니다. 기존 다른 수업과 공용으로 쓰는 VM보다 학생별 전용 VM에서 진행합니다. 이번 웹 컨테이너는 VM의 8080 포트를 사용하며, 수업 전 해당 포트의 사용 여부를 확인합니다.
